# G2 종합 평가 — 안전한 C++ 런타임

이 평가는 공개 입력 A·B와 다른 봉인 입력 C로 진행합니다. 공개 검사를 다시 실행하는 것만으로는 통과할 수 없습니다. 처음 보는 자원 수명, 동시성, ABI 문제를 180분 안에 설명하고 고쳐야 합니다.

## 시작 조건

- 공개 A와 B 전체 통과 커밋이 있다.
- 평가자가 봉인 입력의 SHA-256과 시작 커밋을 기록한다.
- 인터넷, 기준 구현, 이전 답안은 보지 않는다.
- 평가자와 학습자는 같은 Python·Zig 버전과 빌드 대상을 사용한다.

## 과제 A — 잘못된 데이터 수명 고치기 (50분, 30점)

처음 보는 메시지 처리 코드에는 원본 객체 이동, 큐에서 값 꺼내기, 데이터 뷰 보관 과정과 관련된 결함 두 개가 들어 있습니다.

1. 처음 10분 동안 코드를 고치지 않고 소유 관계와 데이터 뷰의 수명이 끝나는 시점을 그립니다.
2. 수명이 끝난 데이터를 읽는 문제를 가장 작게 재현하는 검사를 먼저 작성합니다.
3. 값 복사, 저장 공간 공동 소유, 콜백이 실행되는 동안에만 빌리기 중 하나를 선택해 고칩니다.
4. 선택하지 않은 두 방법의 비용과 실패 양상을 설명합니다.

| 판정 | 점수 |
| --- | ---: |
| 원인을 객체 소유권과 `shared_ptr` 관리 정보 수준에서 설명 | 8 |
| 먼저 작성한 실패 검사가 원래 결함을 재현 | 8 |
| 이동·파괴·재배치 뒤에도 데이터 수명이 안전 | 10 |
| 선택과 대안의 비용 설명 | 4 |

## 과제 B — 종료 경합과 고정 용량 처리기 수리 (80분, 45점)

용량과 콜백 수가 바뀐 이벤트 처리기 또는 큐를 받습니다. 결함은 공개 결함 주입본과 다른 곳에 있습니다.

1. 공유 상태, 상태를 보호하는 수단, 대기 조건을 표로 적습니다.
2. 큐가 가득 찬 상태, 예상치 못한 깨움, 종료 요청, 콜백 안에서 다시 호출하는 상황 가운데 평가자가 고른 두 가지를 관찰용 훅으로 매번 같은 순서로 재현합니다.
3. `sleep` 없이 수리하고 모든 작업 스레드가 끝날 때까지 `join`합니다.
4. 객체 생성 뒤 동적 메모리 할당을 금지한 구간과 반복 횟수의 상한을 코드에서 찾아 설명합니다.

| 판정 | 점수 |
| --- | ---: |
| 상태·뮤텍스·조건 변수 관계가 정확함 | 10 |
| 두 실패 순서를 반복 재생 | 10 |
| 종료·남은 값 처리·최대 용량 규칙 통과 | 15 |
| 동적 메모리 할당과 실행 횟수 상한 설명 | 10 |

## 과제 C — C 경계와 다형성 선택 (50분, 25점)

`Clock`, `Transport`, `Launcher` 중 하나의 요구가 바뀝니다. 음수 데이터, 시간 초과, 정리 함수 호출 가운데 두 가지 이상을 포함합니다.

1. 가상 함수, 템플릿·정적 호출, 함수 테이블이 같은 결과를 내는 검사를 작성합니다.
2. C17 사용자가 포함할 헤더와 불투명 핸들의 생성·해제 책임을 점검합니다.
3. 같은 빌드 대상과 옵션으로 만든 ELF 또는 링커 map을 비교합니다.
4. 한 방법을 선택한 짧은 ADR을 작성합니다.

| 판정 | 점수 |
| --- | ---: |
| 세 구현을 판정하는 검사 코드가 구현과 독립적임 | 7 |
| C 상태·데이터·소유권 경계가 명확함 | 8 |
| 비교 조건과 수치가 재현 가능함 | 5 |
| ADR이 요구와 근거를 연결함 | 5 |

## 통과 기준

- 총점 85점 이상
- 세 과제 모두 70% 이상
- 즉시 불합격 항목 0개
- 같은 시작점으로 독립 검토자가 재현

## 즉시 불합격

- 메모리·정의되지 않은 동작 검사기를 끄거나 `sleep`을 늘려 실패를 숨김
- 수명이 끝난 데이터 뷰, 데이터 경합, 최대 용량 초과, `close()` 뒤에도 끝나지 않은 스레드
- 정리 함수 호출 누락·중복, C 경계로 C++ 예외 또는 객체 배치 구조 전파
- 빌드 대상·컴파일러·옵션이 다른 결과의 크기를 직접 순위 비교
- 개발 PC 실행이나 오브젝트 파일 분석 결과를 실제 Cortex-M·AArch64 실행으로 표현

## 재시험

불합격한 뒤 공개 입력이나 같은 결함만 고쳐 다시 제출할 수는 없습니다. 평가자는 소유 관계, 큐 용량, 콜백 순서, C 데이터의 부호, 빌드 대상 가운데 두 가지 이상을 바꾼 새 봉인 입력을 사용합니다. 7일 안에는 실패한 영역만 90분 동안 재시험할 수 있습니다. 두 번째에도 실패하면 세 과제를 모두 다시 평가합니다.

실제 학습자와 독립 검토자가 이 절차를 수행하기 전에는 G2를 `Assessment-ready`나 `Validated`로 표시하지 않습니다.
