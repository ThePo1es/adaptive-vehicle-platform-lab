# 커리큘럼 코드 안내

이 문서는 저장소의 짧은 코드를 처음 보는 사람도 제목을 추측하지 않고 읽도록 돕습니다. 코드는 파일명과 자동 검사에서 안정적으로 쓰기 위해 남겨 둔 관리 번호입니다.

## 네 가지 코드

| 코드 | 읽는 법 | 무엇을 가리키나 | 예시 |
| --- | --- | --- | --- |
| `G` | 학습 단계 | 큰 학습 챕터 | `G1`: 안전한 C로 데이터와 메모리 다루기 |
| `실습 1-1` | 실습 | 한 챕터 안의 2주 안팎 과제 | `실습 1-1`: 정수와 바이트를 안전하게 변환하기 |
| `G1.1` | 자동화용 실습 코드 | 화면의 실습 번호를 검사기·증거 파일에서 부르는 이름 | `G1.1`은 `실습 1-1`과 같은 과제 |
| `P` | 프로젝트 | 여러 챕터 결과를 합친 공개 포트폴리오 | `P00`: MCU/RTOS ECU 프로젝트 |
| `F` | 고장 시나리오 | 통합 시험에서 의도적으로 주입하는 고장 | `F01`: MCU 태스크 실행 시간 초과 |

`G1`과 `F01`은 같은 계열이 아닙니다. 앞의 글자가 의미를 결정합니다. 문장에서는 이름을 먼저 쓰고 코드를 괄호에 둡니다.

실행 명령의 `G01_LAB_ID`는 실습 선택 환경 변수입니다. 값 `G1.ENTRY`는 1장 진입 확인, `G1.1`은 실습 1-1, `G1.RETEST`는 1장 전체의 두 번째 공개 입력을 뜻합니다.

- 권장: `안전한 C로 데이터와 메모리 다루기(G1)`
- 권장: `고장 시나리오 01: MCU 태스크 실행 시간 초과(F01)`
- 피함: 설명 없이 `G1`, `F1`, `P00`만 사용

## 챕터 이름과 권장 순서

| 권장 순서 | 관리 코드 | 사용자에게 보이는 이름 |
| ---: | --- | --- |
| 1 | G0 | 개발 환경과 검증 기준 준비하기 |
| 2 | G1 | 안전한 C로 데이터와 메모리 다루기 |
| 3 | G2 | 임베디드 C++ 자원 수명과 소유권 다루기 |
| 4 | G3 | ARM 실행 구조와 컴파일 결과 읽기 |
| 5 | G8 | 임베디드 Linux 이미지와 프로세스 운영하기 |
| 6 | G9 | 서비스 인터페이스와 SOME/IP 통신 구현하기 |
| 7 | G10 | AUTOSAR Adaptive 실행·상태·진단·권한 이해하기 |
| 8 | G11A | 안전한 업데이트와 UCM 구현하기 |
| 9 | G4 | Cortex-M 보드 부팅과 인터럽트 구현하기 |
| 10 | G5 | RTOS 태스크와 실시간성 검증하기 |
| 11 | G6 | CAN 통신과 차량 진단 구현하기 |
| 12 | G7 | AUTOSAR Classic 구조로 ECU 기능 묶기 |
| 13 | G11B | MCU–Linux 안전·보안 근거 검토하기 |
| 14 | G12 | MCU–Linux 차량 플랫폼 최종 통합하기 |

관리 코드의 숫자순과 권장 학습 순서가 다른 이유는 G3에서 Linux/Adaptive 축과 MCU/Classic 축이 갈라지기 때문입니다. 기본 경로는 Linux/Adaptive 축을 먼저 완성한 뒤 MCU/Classic 축으로 돌아와 최종 통합합니다.

## 파일명은 왜 그대로인가

`gates/g01/sprint-1.1.md` 같은 경로는 내부 링크, 요구사항 추적, 실행 증거에서 이미 사용됩니다. 학습자에게 보이는 제목은 쉽게 바꾸되, 파일 경로와 관리 코드는 안정적으로 유지합니다. 이 원칙 덕분에 제목을 다듬어도 과거 실행 기록과 Git 이력이 끊기지 않습니다.
