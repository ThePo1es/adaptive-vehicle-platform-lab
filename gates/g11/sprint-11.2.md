# Sprint 11.2 — 패키지 인증과 키 정책

## 시간과 기준 자료

28–38시간을 예상합니다. OpenSSL의 [EVP 서명 문서](https://docs.openssl.org/3.0/man7/evp/), R25-11 Cryptography·IAM·UCM 문서, P04-T2 계약을 사용합니다. 알고리즘, 키 종류, 인코딩, 라이브러리 빌드, 테스트 벡터 출처는 시작 전에 고정합니다.

## 검증 순서

매니페스트 바이트를 엄격한 parser로 읽고 정규 형식을 다시 만든 뒤 서명을 확인합니다. 승인된 키 ID와 역할을 정책에서 찾고, 모든 payload를 descriptor 기반으로 열어 크기와 hash를 검증한 다음 스테이징 권한을 냅니다. 경로 문자열을 확인한 뒤 다시 여는 흐름은 사용하지 않습니다.

## 안내 실습

정상 패키지와 변조된 매니페스트·payload, 알 수 없는 키, 폐기된 키, 잘못된 대상, 비정규 인코딩 입력을 만듭니다. 검증 결과에는 주체, 패키지 ID, 키 ID, 정책 버전, 매니페스트 hash, payload hash를 남기고 키 원문은 남기지 않습니다.

## 독립 실습

교체와 폐기가 포함된 버전형 키 정책을 구현합니다. 이전 정책으로 시작한 검증이 재적재 뒤 어떤 버전으로 끝나는지 정의합니다. 서명 검증과 설치 권한 판정을 분리해 유효한 서명을 가진 무권한 서명자도 거부합니다.

## 전이 과제

검토자가 유효한 서명을 유지한 채 대상 또는 서명자 역할을 바꾼 패키지를 줍니다. 암호학적 유효성과 배포 권한 중 어디서 거부됐는지 추적 기록으로 입증하고 회귀 테스트를 추가합니다.

## 판정 기준

- 정규 바이트와 서명 입력을 고정 입력에서 바이트 단위로 재생
- 매니페스트와 모든 payload 검증이 스테이징 쓰기보다 먼저 끝남
- 알 수 없는 키·폐기 키·역할 불일치가 서로 다른 감사 사유로 거부됨
- 파일 교체와 symlink 입력 모음이 descriptor identity 계약을 우회하지 못함
- 정책 재적재 중 검증이 한 버전으로 일관되게 끝남
- secret, private key, raw credential이 소스·로그·입력 파일에 없음
- T2가 제공하지 못하는 롤백 방지를 릴리스 주장에 넣지 않음

## 실마리

- 서명이 맞아도 대상과 서명자 역할이 허용되지 않을 수 있습니다.
- parser가 보존한 원본과 다시 직렬화한 바이트 중 무엇을 서명하는지 하나로 고정합니다.
- 폐기 정보 자체의 신뢰와 최신성도 가정 목록에 들어갑니다.

## 실패와 보강

payload를 쓴 뒤 서명을 검사하거나, 서명 유효성만으로 설치를 허용하거나, 검증 도중 경로를 다시 열면 재시험합니다. 보강은 payload 하나와 활성 키·폐기 키 두 개로 진행합니다.
