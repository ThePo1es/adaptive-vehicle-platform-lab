# Sprint 11.1 — UCM 범위와 업데이트 위협 모델

## 시간과 기준 자료

24–34시간입니다. R25-11 `Update and Configuration Management`, 관련 Manifest 문서, AUTOSAR [WG-UCM 범위](https://www.autosar.org/working-groups/cross-standard)를 읽습니다. 공식 문서에서 Software Package, Software Cluster, dependency, processing, activation, rollback, history가 쓰이는 절을 근거 장부에 고정합니다.

## 시작 조건

필수 범위는 차량 내부 업데이트 담당 구성요소입니다. 플릿 캠페인 서버, 이동통신 전송, OEM 키 인프라 전체는 다루지 않습니다. OTA 파일 전송과 UCM의 패키지 처리·활성화는 책임을 나눠 그립니다.

## 안내 실습

P04의 로컬 A/B 업데이트 도구를 Software Package, Software Cluster, 대상, 의존성, 차량 상태, Function Group State 관점으로 다시 모델링합니다. 자산, 신뢰 경계, 공격자 능력, 업데이트 진입점을 데이터 흐름도에 표시하고 T1/T2/T3 단계마다 성립하는 보장을 적습니다.

## 독립 실습

패키지 ID, 대상, 버전, 의존성, 호환성, payload hash·크기, 서명 키 ID, 필요한 상태, 활성화 정책을 정규 매니페스트에 넣습니다. parser는 중복 key, 알 수 없는 보안 필드, 타입 혼동, 크기 초과, 의존 순환을 스테이징 전에 거부해야 합니다. 로컬 필드마다 R25-11 매핑 상태를 붙입니다.

## 전이 과제

전이 위협 모델에서는 공격자 능력 하나와 패키지 의존성 하나가 바뀝니다. 새 공격 경로, 무효가 된 가정, 추가할 실패 입력을 갱신합니다. 지원하지 않는 UCM 기능은 `Missing`으로 남깁니다.

## 판정 기준

- 차량 내부 UCM과 플릿 OTA 캠페인의 범위가 문서와 그림에서 분리됨
- 패키지·클러스터·대상·의존성·활성화 용어가 R25-11 절과 연결됨
- 보증 단계마다 신뢰점과 남은 공격 경로가 명시됨
- 정규 매니페스트의 정상·경계·악성 입력 모음이 parser 앞단에서 재생됨
- 의존 순환과 호환되지 않는 대상이 payload 쓰기 전에 거부됨
- 위협 모델 변경이 요구사항·테스트·잔여 위험까지 이어짐

## 힌트

1. TLS 전송 성공만으로 패키지 설치 권한이 생기지는 않습니다.
2. hash는 payload 손상을 찾을 수 있지만 승인한 주체는 확인하지 못합니다.

## UCM 범위 오인

다운로드 클라이언트를 UCM 전체로 소개했거나, 없는 신뢰점을 가정했거나, parser가 모르는 보안 필드를 무시했다면 완료 처리를 미룹니다. 패키지와 클러스터를 하나씩만 남겨 위협 모델과 매니페스트를 다시 맞춥니다.
