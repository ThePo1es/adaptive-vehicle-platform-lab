# Sprint 11.3 — 전송 재개, 스테이징 격리, 저장 공간 고장

## 시간과 기준 자료

22–32시간입니다. R25-11 UCM의 패키지 전송·처리 관련 절, Linux [`openat2(2)`](https://man7.org/linux/man-pages/man2/openat2.2.html), cgroup v2와 파일 시스템 quota 문서를 사용합니다. 전송 방식은 HTTPS 또는 로컬 입력 중 하나로 고정하되 패키지 처리 상태와 분리합니다.

## 안내 실습

조각 번호, byte 범위, 예상 크기, 누적 hash, 임시 객체 ID를 journal에 저장합니다. 중단 뒤에는 서버가 제공한 불변 객체 ID와 로컬 영속 경계를 확인한 경우에만 이어받습니다. 스테이징 root는 활성 slot과 다른 namespace·quota에 둡니다.

## 독립 실습

짧은 읽기, 중복 조각, 겹친 범위, 바뀐 원격 객체, 디스크·inode·quota 고갈, 프로세스 강제 종료를 주입합니다. 부분 파일은 실행·활성화 경로에 보이지 않아야 하며, 실패 뒤 활성 slot과 이전 확정 metadata는 바뀌지 않아야 합니다.

## 전이 과제

전이 시험은 전송을 임의 지점에서 끊고 원격 객체 하나를 바꿉니다. 안전하게 재개할 수 있는 경우와 처음부터 다시 받아야 하는 경우를 판정합니다. 저장 공간을 회수할 때 다른 transaction의 근거를 지우지 않는지도 확인합니다.

## 판정 기준

- 전송 상태와 UCM 처리·활성화 상태가 별도 상태 머신으로 존재
- 재개 전에 원격 객체 ID, 예상 크기, 영속 조각 경계를 확인
- 디스크·quota·inode 고갈에서 활성 slot과 확정 metadata가 유지됨
- 스테이징 경로 이탈, symlink, hard link, rename, 파일 교체 입력 모음 통과
- 중단된 패키지가 실행 파일 탐색 경로나 활성화 후보에 나타나지 않음
- 재시도·정리 횟수와 저장 공간이 설정 상한을 지킴

## 힌트

1. 받은 byte 수가 같아도 원격 객체가 같다고 볼 수는 없습니다.
2. 임시 파일 이름보다 열린 descriptor와 객체 ID를 신뢰합니다.
3. 정리 작업도 중단 뒤 이어갈 수 있는 transaction으로 다룹니다.

## 이어받기 중단선

부분 payload가 활성화 경로에 노출되거나, 공간 부족이 활성 slot을 훼손하거나, 바뀐 객체를 이어받으면 다시 구현합니다. 이어받기 기능을 끈 원자적 전체 전송부터 통과시킨 뒤 범위를 늘립니다.
